# CardForge 数据结构说明

本文档描述编辑器内部的数据模型、字段语义、不变量（invariants）以及「无损」是如何保证的。
对应代码：`src/core/types.ts` 及各 `core/*.ts`。

---

## 1. 总览

```
DocState
├── meta           项目元信息（不写入人物卡）
├── card           NormalizedCard     ← 人物卡（raw + 视图）
├── worldbooks[]   NormalizedWorldbook← 内嵌 / 独立世界书
├── regexes[]      RegexPreset        ← 正则集
├── scripts[]      ScriptCollection   ← 酒馆助手脚本集
├── mvu            MvuState           ← MVU 分析（派生数据）
├── mvuFloors[]    多楼层变量快照
├── baselines[]    导入快照（无损比对）
└── issues[]       校验结果
```

三条例：

1. **raw 优先**：`card.root`、`worldbook.root` 保存导入时的完整对象。
2. **字段级写入**：修改只触碰目标字段，不重建父对象。
3. **导出即投影**：导出时从 raw + 归一化视图重新生成目标格式，不丢未知键。

## 2. 人物卡

### 2.1 归一化结构

```ts
interface NormalizedCard {
  version: 'v1' | 'v2' | 'v3';
  root: Record<string, any>;
  data: CardData;
  rootExtra: Record<string, any>;
  specVersion?: string;
  image?: CardImageInfo;
}
```

| 字段 | V1 | V2 | V3 |
| --- | --- | --- | --- |
| `root` | 原始平面对象 | `{spec, spec_version, data, ...}` | 同 V2 |
| `data` | 与 `root` 同一引用 | `root.data` | `root.data` |
| `rootExtra` | `{}` | `spec/spec_version/data` 之外的根键 | 同 V2 |

> V1 时 `data === root`（同一对象引用），因此对 `data` 的修改直接作用于原始对象。

### 2.2 `data` 字段

**基础**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 角色名，`{{char}}` 的值 |
| `nickname` | string | 否 | V3；显示短名 |
| `creator` | string | 否 | 作者 |
| `character_version` | string | 否 | 角色版本（非规范版本号） |
| `tags` | string[] | 否 | 检索标签 |
| `source` | string \| string[] | 否 | V3；来源链接 |

**正文**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `description` | string | 角色设定主体 |
| `personality` | string | 性格摘要 |
| `scenario` | string | 场景 |
| `first_mes` | string | 主开场白 |
| `alternate_greetings` | string[] | 替代开场白 |
| `group_only_greetings` | string[] | V3；群聊开场 |
| `mes_example` | string | 示例对话，惯例以 `<START>` 分段 |
| `creator_notes` | string | 作者备注 |
| `creator_notes_multilingual` | Record<string,string> | V3 |

**提示词**

| 字段 | 说明 |
| --- | --- |
| `system_prompt` | 覆盖全局系统提示词（空则用全局） |
| `post_history_instructions` | 插在历史之后的指令 |
| `depth_prompt` | `{ prompt, depth, role }`，深度注入 |

**运行设置（SillyTavern 写入卡片时常见，非 V2 规范强制）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `talkativeness` | number | 群聊发言倾向 0–1 |
| `fav` | boolean | 收藏 |
| `world` | string | 绑定的世界书名（内容不在卡内） |

**结构化**

| 字段 | 说明 |
| --- | --- |
| `character_book` | 内嵌世界书，`entries` 为**数组** |
| `extensions` | 第三方扩展容器；酒馆助手脚本在 `extensions.tavern_helper.scripts` |
| `assets` | V3 资源清单 `[{type,uri,name,ext}]` |
| `creation_date` / `modification_date` | V3 Unix 秒 |

未知字段：凡不在上表的键都进入「未知字段」，可视化查看 + JSON 编辑 + 删除（可撤销）。

### 2.3 `character_book`

```json
{
  "name": "北境观测站资料",
  "description": "",
  "scan_depth": 4,
  "token_budget": 2048,
  "recursive_scanning": true,
  "extensions": {},
  "entries": [ { "uid": 0, "key": ["观测站"], "content": "…" } ]
}
```

- `entries` 必须是数组；`scan_depth` / `token_budget` 可为 `null`。
- 编辑器把它映射为 `NormalizedWorldbook`（`shape='array'`, `embeddedInCard=true`）。
- **未同步提示**：编辑独立副本后，卡片内的 `character_book.entries` 仍是旧数据；需点击「同步到卡片」。

### 2.4 图片信息

```ts
interface CardImageInfo {
  dataUrl: string;
  mime: string; fileName?: string; width?: number; height?: number;
  metaChunks: { keyword: string; json: string; spec?: string; specVersion?: string }[];
  otherChunks?: { keyword: string; text: string }[];
}
```

`metaChunks` 保留每个 `chara`/`ccv3` 块的**原始 JSON 文本**，用于：
- 「原始元数据检查」（两个块不一致时提示）；
- 诊断第三方工具写入的异常结构。

## 3. 世界书

### 3.1 结构

```ts
interface NormalizedWorldbook {
  name: string;
  root: Record<string, any>;   // 原始根对象（含全局设置）
  shape: 'record' | 'array' | 'bare';
  entries: WorldbookEntry[];
  origin: 'file' | 'card' | 'new';
  embeddedInCard?: boolean;
}
```

### 3.2 条目字段

| 字段 | 类型 | 默认 | 语义 |
| --- | --- | --- | --- |
| `uid` | number | 必填 | 索引；文件导出时作为 `entries` 的键 |
| `key` | string[] | `[]` | 主关键词 |
| `keysecondary` | string[] | `[]` | 次关键词，配合 `selectiveLogic` |
| `comment` | string | `''` | 备注，不参与触发 |
| `content` | string | `''` | 注入正文 |
| `constant` | boolean | false | 常驻，无条件注入 |
| `selective` | boolean | true | 是否启用次关键词逻辑 |
| `selectiveLogic` | 0–3 | 0 | 0 AND ANY / 1 NOT ALL / 2 NOT ANY / 3 AND ALL |
| `disable` | boolean | false | 禁用 |
| `position` | 0–6 | 0 | 插入位置（见兼容性文档） |
| `depth` | number | 4 | 按深度插入时的楼层深度 |
| `role` | 0–2 | 0 | system / user / assistant |
| `order` | number | 100 | 排序权重（越大越靠前，依据 ST 排序惯例） |
| `probability` | 0–100 | 100 | 触发概率 |
| `useProbability` | boolean | true | 是否执行概率判定 |
| `group` | string | `''` | 包含组；多个用逗号分隔 |
| `groupWeight` | number | 100 | 组内权重 |
| `groupOverride` | boolean | false | 组内强制优先 |
| `scanDepth` | number \| null | null | 覆盖全局扫描深度 |
| `caseSensitive` | boolean \| null | null | 覆盖全局大小写 |
| `matchWholeWords` | boolean \| null | null | 覆盖全局整词匹配 |
| `excludeRecursion` | boolean | false | 被递归排除 |
| `preventRecursion` | boolean | false | 不参与递归触发 |
| `delayUntilRecursion` | boolean | false | 延迟到递归阶段 |
| `vectorized` | boolean | false | 向量化召回（编辑器不模拟） |
| `addMemo` | boolean | true | 生成时附带备注 |
| `useGroupScoring` | boolean \| null | null | 组内评分（版本相关） |
| `sticky` / `cooldown` / `delay` | number | 0 | 按消息计数的时序状态 |
| `automationId` | string | `''` | 自动化关联 |
| `displayIndex` | number | — | **编辑期**排序字段，导出时删除 |

未知字段原样保留（条目编辑器底部「未知字段」）。

### 3.3 不变量

- `uid` 在单本世界书内应唯一；冲突由校验报错，可一键修复。
- 导出为 `record` 时，键为 `String(uid)`；重复 UID 会互相覆盖（因此校验把它列为 error）。
- 条目顺序以 `displayIndex` 为准，与 `order`（触发排序）分离。

## 4. 正则

```ts
interface RegexPreset {
  name: string;
  scripts: RegexScript[];
  root: any;
  shape: 'array' | 'object';
  origin: 'file' | 'character' | 'new';
}
```

`RegexScript` 字段见 `技术实现计划书 §7`。补充约定：

- `id` 在集合内应唯一（校验检查）。
- `findRegex` 以 `/pattern/flags` 存储；解析时取最后一个未转义 `/`。
- `trimStrings` 在匹配前删除；替换串支持 `$1`、`$&`、`$<name>`。
- `minDepth` / `maxDepth` 只在运行时相对楼层有意义；模拟器可传入「楼深」。
- 非标准字段（如 `replace_file`）保留并在 UI 提示「非标准」。

## 5. 酒馆助手脚本

```ts
interface ScriptCollection {
  scripts: TavernScript[];
  root: any;
  shape: 'array' | 'object';
  origin: 'file' | 'character' | 'new';
}
```

`TavernScript.button` 结构：

```json
{ "enabled": true, "buttons": [ { "name": "查看天气", "visible": true } ] }
```

`data` / `export_with` 含义随实现而异，编辑器提供通用 JSON 编辑并原样导出。

## 6. MVU 状态

```ts
interface MvuState {
  flavor: 'mvu' | 'mvubeta' | 'mvuzod' | 'unknown';
  confidence: 'high' | 'medium' | 'low';
  evidence: { flavor, score, signals: { where, detail }[] }[];
  statData: Record<string, any>;
  statSource: 'worldbook' | 'script' | 'imported' | 'empty';
  statSourceDetail?: string;
  schemaFields: { path, type, required, defaultValue?, constraints[] }[];
  schemaNote?: string;
  relatedEntries: { uid, comment, kind }[];
  relatedScripts: { id, name, kind }[];
  floors: { index, statData, label? }[];
}
```

- `statData` 是**值**，不是引用；每次修改通过 `setStatData(新对象)` 触发补丁历史。
- `schemaFields[].path` 使用点路径，数组元素写作 `背包[].名称`。
- `floors` 来自用户导入的变量快照，可用于历史/差异视图。

## 7. 无损机制的实现细节

### 7.1 为什么不会丢未知字段

1. 导入时**不重建**对象：`normalizeCard` 直接引用 `json`（V1）或 `json.data`（V2/V3）。
2. 编辑时**不重建**父对象：表单写入 `d.card.data[key] = value`（immer 只克隆被修改的路径）。
3. 导出时**从 raw 投影**：`serializeCard` 使用 `clone(card.data)` 与 `rootExtra`，未知键随 `data` 一起带出。
4. 唯一会主动删除的情况：
   - 目标 V1 导出时的 `rootExtra`（V1 无根级扩展概念）——导出报告明确列出；
   - 用户手动删除未知字段（可撤销）。

### 7.2 持久化去重

`serializeDoc` 会：
- 内嵌世界书：`root` 置空（其内容由 `card.data.character_book` 承载）。
- 独立世界书：去掉 `root.entries`（避免与归一化条目重复，实测 5 万条从 71.5MB 降到 35.5MB）。
- `card.root.data` 不再重复序列化（只存 `root`，加载时重新取 `data`）。

### 7.3 往返验证

`roundTripCard`：`serialize → JSON.parse → normalize → deepEqual(data)`。
`roundTripPng`：`buildCardPng → readPngInfo → JSON.parse(chara/ccv3) → normalize → deepEqual`。

UI 在「项目首页」和「数据校验」页提供按钮，结果列出差异路径。

## 8. 类型与字段的容错策略

| 异常输入 | 处理 |
| --- | --- |
| `entries` 为数组 / 对象 / 裸 record | 分别识别为 array / record / bare |
| `uid` 缺失或非数字 | 用读入序号补齐 |
| `key` 是字符串 | 包装为单元素数组 |
| `content` 非字符串 | 转为字符串（`null` → `''`） |
| `probability` 非数字 | 保持原值，校验报错 |
| `character_book` 不是对象 | 校验 warning，不强行改写 |
| PNG 无元数据 | 导入报错并说明缺少 `chara`/`ccv3` |
| 正则缺定界符 | 按裸 pattern 处理并提示 |
| 脚本顶层 await / import | 语法检查按异步/模块上下文重试，不误报 |
