## 1. 项目目标与功能范围

### 1.1 目标

把 SillyTavern 人物卡从「一个 JSON 文件」升级为「一个可维护的工程」：

1. 完整读写 Character Card V1/V2/V3 与 PNG 元数据，未知字段零丢失。
2. 世界书（内嵌 / 独立文件）可视化编辑，支持数万条目。
3. 酒馆助手脚本查看、编辑、静态检查（不执行）。
4. 正则规则可视化编辑 + 隔离测试 + 执行链模拟。
5. MVU（mvu / mvubeta / mvuzod）变量的多视图编辑、Schema 静态关联、JSON Patch 模拟。
6. 人物卡前端预览（正则渲染 + MVU 状态栏，HTML 沙箱）。
7. 导入导出、导出前检查、无损往返验证。
8. 本地优先：无服务器、无上传、IndexedDB 持久化。

### 1.2 明确不做（以及原因）

| 不做的能力 | 原因 | 替代方案 |
| --- | --- | --- |
| 执行卡片内 JavaScript / 任意 HTML | 安全底线：导入文件不可信 | 静态语法检查、API 使用分析、只读展示 |
| MVU 运行时真实求值 | 需要 SillyTavern + 助手 + MVU 运行环境 | 静态解析 + 手动导入变量快照 + Patch 模拟 |
| 向量化语义召回 | 需要嵌入模型与索引服务 | 模拟器显式标记「未实现」 |
| CHARX 完整解包 | 需要 ZIP 解析与资源落盘，收益低于风险 | 识别格式并提示取出 `card.json` 导入 |
| 全局正则规则直接写入 SillyTavern 设置 | 浏览器无法访问 ST 的服务器端设置 | 导出 JSON，供正则扩展导入 |

## 2. 技术栈选择及理由

| 选择 | 理由 | 放弃的方案 |
| --- | --- | --- |
| **TypeScript + React 18 + Vite** | 数据模型复杂，类型是主要防错手段；Vite 冷启动快、Worker 支持好 | Vue（团队更熟 React 生态工具链）、Next.js（需要服务端，与本地优先冲突） |
| **Zustand + immer（patch 历史）** | 单一文档树 + 结构共享；`produceWithPatches` 免费获得可逆补丁，撤销/重做无需深拷贝 | Redux（样板多）、手写 diff（重复造轮子） |
| **CodeMirror 6** | 按需加载语言包、体积可控、支持大文档、易于自定义主题 | Monaco（体积与 Worker 配置成本高） |
| **自研虚拟列表** | 需求单一（固定行高），自研 60 行即可，避免额外依赖 | react-window（可行，但样式与滚动容器控制更绕） |
| **自研 PNG 读写 + CRC32** | 只需 tEXt/zTXt/iTXt；避免引入图像库；写入时字节级保留其他块 | pngjs / upng（Node 侧 API，浏览器打包体积大） |
| **Web Worker × 2** | 正则测试与全文搜索是唯一可能阻塞主线程的计算 | 主线程 + 时间切片（正则无法中断） |
| **immer patches 作为历史** | 内存友好，条目级逆操作 | 全量快照（50k 条目时不可接受） |
| **纯 CSS（CSS 变量主题）** | 高密度 IDE 布局需要精细控制；无构建期依赖 | Tailwind（可行，但本项目的样式多为一次性布局） |

运行时依赖仅 7 个（react、react-dom、zustand、immer、diff、CodeMirror 系列），全部为常规库，无网络请求。

## 4. 完整数据结构设计

### 4.1 原则

1. **raw 是唯一事实来源**：`card.root` / `wb.root` 保留导入时的原始对象。
2. **归一化只是视图**：`NormalizedCard` / `NormalizedWorldbook` 提供便捷字段与索引，不参与「重建后导出」。
3. **字段级写入**：所有编辑通过 `mutate` 在 draft 上 `Object.assign(entry, patch)` 或 `data[key] = v`，从不 `{...data}` 重建，未知字段自然保留。
4. **持久化去重**：世界书 `root.entries` 与归一化 `entries` 重复时，落盘只保留归一化版本。

### 4.2 文档树

```ts
interface DocState {
  meta: { id, name, createdAt, updatedAt, sourceFileName?, cardVersion? };
  card: NormalizedCard | null;          // 人物卡
  worldbooks: NormalizedWorldbook[];    // 内嵌 + 独立导入
  regexes: RegexPreset[];               // 正则集
  scripts: ScriptCollection[];          // 脚本集
  mvu: MvuState | null;                 // MVU 分析结果（派生 + 用户导入）
  mvuFloors: { index, statData, label? }[];
  baselines: { key, label, json, at }[];// 导入快照，用于无损比对
  issues: ValidationIssue[];
}
```

### 4.3 历史

每次 `mutate` 产出 `{ forward, inverse }` 两组补丁；同字段 700ms 内的连续输入合并为一步（`coalesce` 键），避免每敲一个字产生一步历史。

## 5. 人物卡数据模型

```ts
type CardVersion = 'v1' | 'v2' | 'v3';

interface NormalizedCard {
  version: CardVersion;
  root: Record<string, any>;          // V2/V3: { spec, spec_version, data, ...unknownRoot }
  data: CardData;                     // V1 时 root === data
  rootExtra: Record<string, any>;     // 根级未知字段
  specVersion?: string;
  image?: CardImageInfo;
}
```

**版本识别顺序**

1. `spec === 'chara_card_v3'` → V3；`chara_card_v2` → V2。
2. `spec` 含 `v3`/`v2` 字样 → 按对应版本容错读取。
3. 无 `spec` 但存在 `data` 对象且根级无 `name` → 按 V2 结构容错读取。
4. 其余 → V1（平面结构，`data === root`）。

**导出策略**

| 目标 | 行为 | 明确提示 |
| --- | --- | --- |
| V3 | `{spec:'chara_card_v3', spec_version:'3.0', data, ...rootExtra}` | 不自动补 V3 专属字段 |
| V2 | 同上，spec 改 v2 | 列出会被 V2 读取器忽略的 V3 字段 |
| V1 | 把 `data` 摊平；`rootExtra` 丢弃 | 列出内嵌世界书 / assets / 根级扩展的丢失风险 |

**字段元数据**：`CARD_FIELDS` 定义 29 个规范字段（含 V3 追加字段），驱动表单渲染；不在此表内的字段进入「未知字段」面板，可 JSON 编辑、可删除（可撤销）。

## 6. 世界书数据模型

```ts
interface WorldbookEntry {
  uid: number;
  key: string[]; keysecondary: string[];
  comment: string; content: string;
  constant: boolean; selective: boolean; selectiveLogic: 0|1|2|3;
  disable: boolean; position: number; depth: number; role: number; order: number;
  probability: number; useProbability: boolean;
  group: string; groupWeight: number; groupOverride: boolean;
  scanDepth: number|null; caseSensitive: boolean|null; matchWholeWords: boolean|null;
  excludeRecursion: boolean; preventRecursion: boolean; delayUntilRecursion: boolean;
  vectorized: boolean; addMemo: boolean; useGroupScoring: boolean|null;
  sticky: number; cooldown: number; delay: number; automationId: string;
  [k: string]: any;                    // 未知扩展字段
}
```

**三种文件形状**（读取都支持，导出按来源保持）

| 形状 | 例子 | 来源 |
| --- | --- | --- |
| `record` | `{"entries":{"0":{...},"1":{...}}}` | SillyTavern 世界书导出文件 |
| `array` | `{"entries":[{...}]}` | Character Card V2/V3 `character_book` |
| `bare` | `{"0":{...},"1":{...}}` | 部分旧工具/手写文件 |

`displayIndex` 是编辑期排序字段，导出时删除。

**默认值**：见 `ENTRY_DEFAULTS`（order=100、probability=100、depth=4、selective=true、useProbability=true…）。只补缺失键，不覆盖已有值（包括 `null`，`null` 表示继承全局）。

## 7. 正则数据模型

```ts
interface RegexScript {
  id: string; scriptName: string;
  findRegex: string;        // "/pattern/flags"
  replaceString: string;
  trimStrings: string[];
  placement: number[];      // 1..6
  disabled: boolean; markdownOnly: boolean; promptOnly: boolean;
  runOnEdit: boolean;
  substituteRegex: 0|1|2;   // 不替换 / 原文替换 / 转义替换
  minDepth: number|null; maxDepth: number|null;
  replace_file?: string;    // 非标准字段，存在则保留
  [k: string]: any;
}
```

**placement 取值**（标签见 `REGEX_PLACEMENT_LABELS`，证据等级：惯例）

| 值 | 含义 |
| --- | --- |
| 1 | AI 输出的 Markdown 显示 |
| 2 | 用户输入 |
| 3 | AI 输出（发送给模型前） |
| 4 | 斜杠命令 |
| 5 | 世界书内容 |
| 6 | 推理过程 |

**findRegex 解析**：从字符串两端找未转义的 `/`，中间为 pattern，末尾为 flags（`dgimsuvy` 子集）。缺少定界符时按裸 pattern 处理并标注警告（真实运行时是否容错随版本而异）。

**安全**：所有测试在 Worker 中执行，主线程 400ms 超时后 `terminate()`；静态启发式检测嵌套量词、`(.*)*`、重叠交替等高风险结构。

## 8. 酒馆助手脚本数据模型

```ts
interface TavernScript {
  id: string; name: string; content: string;   // JS 源码
  info?: string; enabled?: boolean;
  button?: { enabled?: boolean; buttons: { name, visible }[] };
  data?: Record<string, any>;
  export_with?: Record<string, any>;
  [k: string]: any;
}
```

**存放位置**（读取顺序）

1. `data.extensions.tavern_helper.scripts`（卡片内脚本，最常见）
2. `data.extensions.tavern_helper_scripts`（少数卡的变体）
3. 全局设置形态 `{ type:'script', value:{...}, enabled }`（导入时解包）
4. 独立 JSON（数组 / `{scripts:[…]}` / 以 id 为键的对象）

**静态分析**：`analyzeScript` 提取 import / importScripts / 助手 API 调用 / 事件订阅 / fetch / eval / iframe / 按钮数；`checkSyntax` 用 `new Function(code)` 仅编译不执行，并对顶层 `await`、ES module 语法做「按模块/异步上下文重试」，避免误报。

## 9. MVU 多版本适配模型

```ts
type MvuFlavor = 'mvu' | 'mvubeta' | 'mvuzod' | 'unknown';

interface MvuState {
  flavor; confidence; evidence[];
  statData; statSource: 'worldbook'|'script'|'imported'|'empty';
  schemaFields: MvuSchemaField[];
  relatedEntries; relatedScripts; floors;
}
```

**识别**：对脚本与世界书条目做加权信号打分（`registerVariableSchema` +6、`z.object` +4、Zod 类型构造器 +2、`stat_data` +2/+3、`[InitVar]` 条目 +3、`display_data`/`delta_data` +1…）。`mvuzod` 是 `mvu` 的超集，因此当出现明确的 `registerVariableSchema` 时，即使基础版信号同样密集也判为高置信度。

**变量来源优先级**：用户导入的变量快照 > 世界书 `[InitVar]` 类条目（YAML/JSON 解析）> 空。

**Schema 静态推断**：解析 `z.object({...})` 嵌套结构，识别 `z.string/number/boolean/array/object/enum/literal/union/tuple/record/coerce/null/any`，链式 `.optional/.nullable/.default/.min/.max/.int/.positive/.regex/.describe`；对 `.transform/.refine/z.record/展开语法/动态字段` 显式标记「运行时逻辑，静态不可判定」，不假装理解。

**Patch**：实现 RFC 6902 的 add/remove/replace/move/copy/test，并支持把 `_.set('a.b', v)` 风格转换为补丁（数值累加等运行时语义按字面写入，已标注差异）。

## 10. 模块间数据流

```
文件 ──importFile──▶ sniffJson ──▶ normalizeCard / parseWorldbook / parseRegex / parseScript
                                        │
                                        ▼
                                   DocState（store）
        ┌───────────────┬───────────────┼───────────────┬──────────────┐
        ▼               ▼               ▼               ▼              ▼
   Character 表单   Worldbook 编辑器  Regex 编辑器   Scripts 编辑器   MVU 视图
        │               │               │               │              │
        └───────────────┴──── mutate(recipe) ───────────┴──────────────┘
                                        │
                     ┌──────────────────┼──────────────────┐
                     ▼                  ▼                  ▼
              immer patches        去抖持久化         自动校验（小项目）
              （撤销/重做）      IndexedDB（大项目降频）   问题面板
                                        │
                                        ▼
                               exporter（导出前检查 / PNG 元数据）
```

**内嵌世界书双向关系**

- 导入：`extractEmbeddedWorldbook(card)` → 独立的 `NormalizedWorldbook`，标记 `embeddedInCard`。
- 编辑：只改独立世界书；点击「同步到卡片」才写回 `data.character_book.entries`（数组形状、去 `displayIndex`）。
- 导出：`serializeCard` 直接序列化 `card.data`，因此未同步的改动不会意外进入人物卡（首页与检查器会提示存在未同步副本）。

## 13. 导入导出机制

**导入识别**（`sniffJson`，按优先级）

1. `spec` 为 chara_card_*，或 `data.name`，或命中 ≥2 个人物卡特征字段 → 人物卡
2. 含 `entries`（对象或数组）→ 世界书（数组元素含 `findRegex` 则判为正则）
3. 数组且首元素含 `findRegex` → 正则
4. 数组/对象且首元素含 `content` + `name|id` → 脚本
5. 其余 → 明确报错，并说明四类结构的判据

**PNG 读取**：遍历块 → `tEXt`（latin1）、`zTXt`（DecompressionStream('deflate')）、`iTXt`（UTF-8 / 压缩）→ 关键字 `chara` / `ccv3` → base64 解码 → JSON。多个块时优先 `chara_card_v3`，并提示块数量与差异。

**PNG 写入**：字节级复制原图所有块（含 CRC），删除旧 `chara`/`ccv3`，在 IEND 前插入新的 `tEXt`（base64 为 ASCII，等价 latin1）。无原图时用 Canvas 生成 512×768 占位图（明确告知）。

**导出前检查**（`checkBeforeExport`）：阻断项（无名称等）、警告（版本字段降级、V1 丢世界书）、提示（源版本差异、占位图）。

## 14. 大型数据性能优化方案

| 问题 | 方案 | 实测（Node / Chromium） |
| --- | --- | --- |
| 列表渲染 | 虚拟列表，行高固定 40px | 5 万条目 DOM 行数 ≈34 |
| 搜索 | Worker 内小写化文本索引 + 增量更新 | 5 万条查询 ~70–220ms（含 150ms 人为等待） |
| 解析 | 单次遍历 + 只补缺失默认值 | 1 万 191ms / 5 万 681–721ms |
| 序列化 | 去掉 `root.entries` 重复 | 5 万：355ms/71.5MB → 177ms/35.5MB |
| 统计 / 重复检测 | 条目 >8000 时改为按需计算 | 避免每次按键 O(n) 重算 |
| 自动校验 | 条目 >8000 暂停自动校验 | 避免编辑卡顿，面板显示「已暂停」 |
| 自动保存 | 900ms 防抖；>15000 条降频 5s | 5 万条手动保存 30MB 可用 |
| 历史 | immer 补丁而非快照 | 内存 ≈ 补丁体积，上限 150 步 |
| 正则 | Worker + 超时终止 | 灾难性回溯不会冻结主线程 |

## 15. 数据校验及错误处理方案

校验维度（`validateAll`）：

- 人物卡：名称必填、字段类型、替代开场白元素类型、`depth_prompt` 结构、PNG 块一致性。
- 世界书：UID 重复、空/无效关键词、死条目、重复关键词、position/role/probability/selectiveLogic 取值、空正文、超长正文。
- 正则：编译失败、格式不标准、placement 缺失、markdownOnly+promptOnly 冲突、minDepth>maxDepth、替换串引用不存在的组、回溯风险。
- 脚本：语法错误、id 重复、eval/fetch/iframe 提示、空内容。
- MVU：变量来源缺失、Schema 类型/范围不符、静态不可判定项。
- 图片：无元数据块、chara/ccv3 内容不一致、V1 平面元数据。

**错误处理原则**：解析失败给出「哪个阶段 + 原因 + 下一步」；不使用空 catch 吞错；导入失败不改变现有文档（先解析成功再 `set`）。

## 16. 安全机制

1. 纯前端、无网络请求（可离线打开构建产物）。
2. 不执行导入的 JS；语法检查仅编译。
3. HTML 预览使用 `sandbox="allow-scripts"`（无 `allow-same-origin`），无法读取父页面与 IndexedDB。
4. 正则测试在 Worker 中执行并强制超时终止。
5. `download` 导出为本地文件，不经服务器。
6. 导入大文件先解析、后替换，失败保持原状。
7. 所有编辑可撤销；未知字段默认保留。
8. XSS 面：卡片文本经 `markdownToHtml` 先转义再渲染；正则产生的 HTML 一律进沙箱。
