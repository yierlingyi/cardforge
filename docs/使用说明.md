# CardForge 使用说明

## 1. 启动

```bash
npm install
npm run dev        # http://localhost:5178
```

生产构建：

```bash
npm run build      # 产物在 dist/
npm run preview    # 本地预览构建产物（http://localhost:5179）
```

首次打开会自动载入内置示例项目（星见澪），便于直接体验各模块。也可以随时在「项目首页」导入自己的卡片。

> 所有数据保存在浏览器的 IndexedDB（数据库名 `cardforge`）。换浏览器/清理站点数据会导致丢失，重要项目请用「项目设置 → 导出项目备份」另存。

## 2. 界面总览

```
┌ 顶栏：品牌 · 项目名 · 版本 · 撤销/重做 · 搜索 · 导入 · 导出 · 保存状态 · 主题 ┐
├ 标签栏：首页 / 各模块（可关闭）                                              ┤
├ 左侧导航 ┬ 主工作区（每页 1–3 栏）                                          ┤
│          └ 底部面板：问题 / 面板搜索 / 运行日志                              │
└ 状态栏：编码 · 校验计数 · 世界书规模 · token · MVU 版本 · 保存时间           ┘
```

- 左侧栏可用 `Ctrl+B` 或左下角小按钮折叠。
- 底部问题面板点击任意一条会跳到对应页面并选中相应条目/规则。

## 3. 导入

点顶栏「导入」（`Ctrl+O`），可以：

- 拖入文件：`.json` / `.png` / `.charx`
- 或直接粘贴 JSON 文本

**自动识别**：人物卡（V1/V2/V3）、世界书、正则集、脚本集。识别失败会明确告诉你它在找什么（`spec`、`entries`、`findRegex`、`content`）。

- **PNG**：读取 `chara` / `ccv3` 元数据块，不是识别图片内容。没有任何文本块时会提示「可能是普通图片」。
- **CHARX**：识别但不解包，会提示解压后导入 `card.json`。
- **导入世界书**不会覆盖现有世界书，而是作为新的一本加入；名称冲突会自动加序号。

导入成功后，原始数据会自动记录一份快照（「历史记录」页可对比）。

---

## 4. 人物卡编辑

左侧按字段分组（基础/正文/提示词/运行设置/结构化数据/未知字段），中间是表单，右侧是检查器。

- 长文本字段提供「预览 / 全屏 / 复制 / 清空」，并显示字符数与 token 估算。
- 「未知字段」分组列出所有非规范字段，可查看、JSON 编辑、删除（可撤销）。
- 左栏顶部可按字段名/key 搜索（如 `first_mes`），点击结果跳到对应分组。
- 检查器里可以看：识别版本、根级扩展、data 字段数、图片元数据、与快照的差异、原始 JSON。
- 顶部「记录快照」用于在关键改动前留一个对比基线。

> 字段写入是「就地修改单个键」，不会重建整个 data 对象，所以第三方扩展不会因为保存而消失。

## 5. 世界书

### 5.1 管理

顶部可选择世界书，右侧按钮：重命名 / 复制 / 合并 / 导出 / 同步到卡片 / 新建条目 / 删除。

- **内嵌世界书**会显示「内嵌于人物卡」标记。编辑后需点「同步到卡片」才会写回 `data.character_book`；首页与检查器会提示存在未同步副本。
- **合并**：可选「UID 冲突重新分配」与「关键词已存在则跳过」。
- **同步到卡片**：按数组形状写回，并去掉编辑期字段。

### 5.2 浏览与批量

五种视图：列表（虚拟滚动）/ 卡片（前 240 条）/ 关键词索引 / 关系视图（包含组 + 共用关键词）/ JSON。

列表上方：

- 搜索：备注、关键词、正文、UID。条目 ≥1200 时使用 Worker 索引，编辑时增量更新。
- 筛选：全部 / 已启用 / 已禁用 / 常驻 / 失效（永不可触发）/ 重复关键词 / 包含组 / 空正文 / 超长。
- 排序：默认顺序 / UID / 触发顺序 / 正文长度 / 关键词数 / 备注名。
- 多选：单击选中，`Ctrl` 切换，`Shift` 范围选择；出现批量栏可启用、禁用、批量设置、删除。
- 拖拽排序：默认顺序且无搜索时，直接拖动条目行调整顺序。
- 右键菜单：编辑、启用/禁用、常驻切换、复制条目、复制 JSON/正文、删除。

> 大世界书（>8000 条）会自动关闭「重复关键词」实时标记与统计计算，检查器提供「计算统计」按钮；底部自动校验也会暂停，点「重新校验」手动执行。

### 5.3 编辑条目

- 备注、UID（冲突会提示）、启用/禁用、常驻、选择性、概率开关。
- 触发条件：主/次关键词、选择性逻辑、概率、扫描深度、大小写、整词。
- 插入设置：位置、深度、角色、顺序、包含组与权重、组覆盖。
- 正文：全屏编辑、字符/token 计数、空正文警告。
- 递归与时序、其他字段、未知字段（JSON）。

右侧检查器显示条目统计、关键词共用情况、原始 JSON。

### 5.4 触发模拟

点检查器「触发模拟」：

1. 添加模拟消息（用户/角色），或清空只测常驻。
2. 设置扫描深度、随机种子、token 预算、递归、概率判定、大小写、整词。
3. 运行后查看：每条条目的状态与原因、命中的关键词、最终注入顺序、包含组决策、规则分级说明。

相同种子 + 相同输入可复现结果。规则说明里会标注「精确 / 近似 / 未实现」。

## 6. 正则

左侧规则列表（可排序、启用/禁用），右侧四个标签：

- **规则编辑**：`findRegex` 文本（点「应用文本」生效）、flags/捕获组/风险提示、替换串、placement、开关、深度、trimStrings、非标准字段。
- **正则测试**：输入测试文本 → 运行 → 匹配明细（位置、捕获组）、替换结果、原文/结果并排。
- **执行链模拟**：按顺序跑全部启用规则，显示每一步的输入输出、跳过原因（placement/深度/禁用）、耗时。
- **JSON**：单条规则原始结构。

安全：

- 测试在 Worker 中执行，400ms 超时终止。
- 检测到嵌套量词等高风险结构会提前警告。
- 死循环式的零宽匹配已做 `lastIndex++` 保护。

导出为数组（可导入 SillyTavern 正则扩展）；「写回卡片」会写入 `data.extensions.regex`。

## 7. 酒馆助手脚本

- 左列表显示名称、行数、大小、按钮数、import 数、语法状态；支持搜索与排序。
- 右侧标签：
  - **代码**：CodeMirror 编辑、格式化（基础缩进，非 Prettier）、语法检查（只编译不执行）、只读模式。
  - **分析**：语法结果、import/importScripts、助手 API 调用、事件、fetch/eval/iframe/存储提示、与其他脚本的名称引用关系。
  - **按钮**：`button.enabled` 与按钮列表（名称、可见）。
  - **数据**：`data` / `export_with` JSON 编辑。
  - **JSON**：完整对象。

**安全**：编辑器不会执行脚本，也不提供运行时沙箱执行入口。语法检查使用 `new Function` 编译，脚本体不会运行。

「写回卡片」写入 `data.extensions.tavern_helper.scripts`。

## 8. MVU 变量

顶部显示识别版本、置信度、变量来源。标签：

| 标签 | 用途 |
| --- | --- |
| 树形视图 | 展开/折叠、类型着色、Schema 类型徽章、错误标记、搜索过滤、复制 JSON Pointer |
| 表格视图 | 扁平化叶子节点，按路径/值排序，适合大量属性 |
| JSON | 直接编辑整棵变量树，应用前校验 |
| 差异 | 与楼层或手动基线对比 |
| 历史楼层 | 楼层列表，任意两层对比，与当前补丁数 |
| Schema | Zod 静态推断字段表、约束、数据校验、仅数据/仅 Schema 路径 |
| Patch 测试 | 输入 JSON Patch 或 `_.set(...)`，查看变更、错误、Schema 校验，确认后再应用 |

编辑节点：在树/表中选中 → 右侧检查器选择类型 → 修改值 → 应用。对象/数组可「在此节点下添加」。

导入变量：支持单个对象、`[{stat_data:{...}}]`、`{floors:[...]}`。

> Schema 是静态推断结果；`.transform/.refine/z.record` 等会被标注为「运行时逻辑，静态不可判定」。

## 9. 前端预览

- 设备：桌面 900×640 / 移动 390×720 / 窄屏 320×640 / 自定义。
- 选择主开场白或替代开场白，编辑模拟用户消息。
- 开关：应用正则（placement=1）、显示原文、显示 MVU 状态栏。
- 含 HTML 的内容会在 `sandbox="allow-scripts"` 的 iframe 中渲染（无同源权限）。
- 「导出预览 HTML」生成一个独立 HTML 文件。

## 10. 校验、历史与设置

**数据校验**：按级别/范围筛选，点「定位」跳转；展示导出前检查（按目标版本）、无损往返测试、完整性快照；可导出 JSON 报告。

**历史记录**：左侧是补丁历史（最新在上），点某一步回退到该步之前；导入快照可查看与当前的差异。

**项目设置**：项目重命名、备份导出、主题/字号/自动保存、模拟默认值、正则超时、本地存储项目列表、清空数据、快捷键表、能力边界。

## 11. 典型工作流

### 11.1 把 V2 卡升级为 V3 并补全字段

1. 导入 PNG/JSON → 顶栏确认版本徽章为 V2。
2. 人物卡页补齐 nickname / 多语言备注 / assets（可选）。
3. 导出 → 选 V3 → 看报告（会列出 V2→V3 的保留项）→ 下载 PNG。
4. 用「无损往返测试（PNG V3）」验证元数据可回读。

### 11.2 给大世界书做批量整理

1. 导入 1 万条世界书 → 列表切到「失效」筛选，看有多少条永远不会触发。
2. 多选 → 批量设置扫描深度/位置，或删除。
3. 切「重复关键词」筛选 → 在检查器看共用情况 → 用包含组或次关键词区分。
4. 「触发模拟」输入一段聊天，确认注入顺序符合预期。

### 11.3 调试一条正则

1. 正则页 → 选中规则 → 「正则测试」。
2. 粘贴真实消息 → 运行 → 看捕获组是否符合预期。
3. 调整 `replaceString`（点 `$1` 按钮快速插入）→ 再测。
4. 切「执行链模拟」，确认它在整个规则链中的位置与影响。

### 11.4 给 MVU 卡做变量体检

1. MVU 页确认版本与来源（应为世界书初始化）。
2. 「Schema」标签查看类型/范围问题（如生命 180 越界）。
3. 「Patch 测试」输入一次运行时更新，确认路径与结果。
4. 导入多楼层变量 → 「历史楼层」看变量演化。

## 13. 常见问题

**Q：为什么改了世界书，人物卡里还是旧的？**
A：内嵌世界书是独立副本。点「同步到卡片」，或在导出前确认首页没有「存在内嵌副本」提示。

**Q：PNG 导出后 SillyTavern 读不到角色？**
A：检查导出报告里是否有「角色名称为空」；确认目标版本与客户端一致；用「无损往返测试 → PNG」验证元数据块；确认 PNG 未被其他工具二次压缩（部分压缩工具会删除文本块）。

**Q：大世界书编辑有点卡？**
A：>8000 条时已自动关闭实时统计与自动校验；搜索走 Worker。若仍卡，检查是否停留在「卡片视图」（最多 240 条）或 JSON 视图（会生成整本 JSON）。

**Q：正则测试一直超时？**
A：这是保护机制。表达式可能包含灾难性回溯（如 `(a+)+`），请改写为更精确的模式。可在设置中调整超时阈值（不建议调大）。

**Q：脚本为什么不能运行？**
A：安全策略：不执行导入的 JavaScript。请到 SillyTavern 中运行；本工具只做编辑与静态检查。

**Q：数据存在哪里？会上传吗？**
A：IndexedDB（本地）。整个应用没有任何网络请求；构建产物可离线打开。

**Q：为什么 MVU 显示「置信度 medium」？**
A：识别是基于信号的启发式。展开「识别信息」看证据；若与实际不符，可手动导入变量，或按 `src/core/mvu.ts` 的适配层补充信号。

## 14. 排错

- 界面白屏：打开控制台看是否有渲染异常；页面有错误边界，会显示堆栈与「重新加载」。
- 无法保存：检查浏览器是否禁用了 IndexedDB（隐私模式/站点设置）；状态栏会显示「保存失败」。
- 导入报「无法识别」：用文本编辑器确认 JSON 根结构，对照提示里的四类判据。
- 项目丢失：设置页的「最近项目」列表可重新打开；若已清空存储则无法恢复（请定期导出备份）。
