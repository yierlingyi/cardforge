# 各格式兼容性说明

本文件说明 CardForge 实际支持到什么程度，以及哪些细节是**确定**的、哪些是**惯例**、哪些**尚未验证**。

证据等级：

- **规范**：有公开规范或标准文本支撑（PNG、RFC 6902 等）。
- **惯例**：SillyTavern 生态中广泛使用的结构，可从大量真实样本观察，但不同版本可能有差异。
- **待验证**：本环境无法对照指定运行时版本逐条确认；实现上做容错处理，UI 与文档明确提示。

---

## 1. 人物卡版本

| 版本 | 识别依据 | 读取 | 写入 | 说明 |
| --- | --- | --- | --- | --- |
| V1 | 无 `spec`，平面字段 | 完整 | 完整（摊平 `data`） | V1 无世界书/扩展概念；导出会丢 `rootExtra` 并明确警告 |
| V2 | `spec = chara_card_v2` | 完整 | 完整 | 规范字段 + `extensions` |
| V3 | `spec = chara_card_v3` | 完整 | 完整 | V2 超集；新增 nickname / assets / source / 多语言备注 / 时间戳 / 群聊开场 |
| 容错 | `spec` 变体、只有 `data` 无 spec | 按 V2 读取 | 按所选版本写入 | 校验面板会提示「按 XX 容错读取」 |

**V3 追加字段**（写入 V2 时仍保留在 `data` 中，但提示读取器可能忽略）：

`nickname`、`creator_notes_multilingual`、`source`、`group_only_greetings`、`creation_date`、`modification_date`、`assets`。

**版本号不做强制校验**：`spec_version` 原样保留与展示，不因 `2.0`/`2.1` 之类差异拒绝加载。

## 2. PNG 人物卡元数据

### 2.1 读取

| 块类型 | 编码 | 处理 |
| --- | --- | --- |
| `tEXt` | 关键字 + `\0` + Latin-1 文本 | 直接解码 |
| `zTXt` | 关键字 + `\0` + 方法字节 + deflate 数据 | `DecompressionStream('deflate')` |
| `iTXt` | 关键字 + `\0` + 压缩标志 + 方法 + 语言标签 + 译文关键字 + UTF-8 文本 | 按标志解压或直读 |

> 规范依据：PNG 规范对文本块的定义（关键字 1–79 字节 Latin-1、`\0` 分隔等）。

### 2.2 人物卡关键字

| 关键字 | 内容 | 证据等级 |
| --- | --- | --- |
| `chara` | base64(JSON)。V1 为平面 JSON；V2/V3 为 `{spec, spec_version, data}` | **惯例** |
| `ccv3` | base64(JSON)，V3 卡片 | **惯例**（写入端按 V3 规范约定使用；不同工具是否都写此块**待验证**） |

**双块处理**：

1. 优先选择 `spec = chara_card_v3` 的块；
2. 否则选 `chara`；
3. 两者内容不一致时，校验面板 warning（「常见于手工改卡」），不修改任何一方；
4. 导出时按目标版本重写：V3 写 `chara` + `ccv3`，V2/V1 只写 `chara`，并删除旧块（避免重复）。

### 2.3 写入

- 字节级复制原 PNG 的**所有其他块**（含 CRC），包括 `IHDR`、`IDAT`、`tIME`、`pHYs`、私有块。
- 在 `IEND` 前插入新的 `tEXt` 块；base64 为 ASCII，因此 Latin-1 编码安全。
- 重复写入不会产生重复 `chara`/`ccv3`（自测覆盖）。
- 无原图时生成 512×768 占位图（Canvas 绘制，纯本地）。

**不做的事**：不重编码像素、不优化压缩、不写入 APNG 动画帧。因此除元数据外，图片字节保持原样。

## 3. 世界书

### 3.1 文件形状

| 形状 | 结构 | 支持 |
| --- | --- | --- |
| `record` | `{"entries":{"0":{...}}}` | 读 / 写（SillyTavern 导出格式） |
| `array` | `{"entries":[{...}]}` | 读 / 写（卡片 `character_book`） |
| `bare` | `{"0":{...}}` | 读；导出统一为 `record` |

导出时会保留根级其他键（`name`、`description`、`scan_depth`、`token_budget`、`recursive_scanning`、`extensions` 等），但删除编辑期的 `displayIndex`。

### 3.2 字段兼容

**完全支持（读写 + UI）**：`uid`、`key`、`keysecondary`、`comment`、`content`、`constant`、`selective`、`selectiveLogic`、`disable`、`position`、`depth`、`role`、`order`、`probability`、`useProbability`、`group`、`groupWeight`、`groupOverride`、`scanDepth`、`caseSensitive`、`matchWholeWords`、`excludeRecursion`、`preventRecursion`、`delayUntilRecursion`、`vectorized`、`addMemo`、`useGroupScoring`、`sticky`、`cooldown`、`delay`、`automationId`。

**保留但不解释**：任何未知键（在条目底部展示 JSON）。

### 3.3 枚举值（证据等级：惯例）

**position**

| 值 | 含义 | 证据等级 |
| --- | --- | --- |
| 0 | 角色定义之前 | 惯例 |
| 1 | 角色定义之后 | 惯例 |
| 2 | 作者注释之前 | 惯例 |
| 3 | 作者注释之后 | 惯例 |
| 4 | 按深度插入（`@D`） | 惯例 |
| 5 | 示例消息之前 | **待验证**（不同版本可能新增） |
| 6 | 示例消息之后 | **待验证** |

编辑器对未知数值只做 warning，不强制改值。

**role**：0 = system、1 = user、2 = assistant（惯例）。

**selectiveLogic**：

| 值 | 语义 |
| --- | --- |
| 0 | AND ANY：主键命中 + 任一辅键命中 |
| 1 | NOT ALL：主键命中 + 辅键未全部命中 |
| 2 | NOT ANY：主键命中 + 辅键全不命中 |
| 3 | AND ALL：主键与辅键全部命中 |

> 0/1/2 语义可从 ST 世界书 UI 的选项描述观察；3（AND ALL）属于较新加入，**待验证**在旧版本中的表现。

### 3.4 触发规则的实现程度

| 规则 | 实现 | 说明 |
| --- | --- | --- |
| 扫描深度（条目覆盖全局） | 精确 | 取最近 N 条消息拼接 |
| 子串匹配 / 大小写 / 整词 | 精确 | 整词用 `\b` 边界 |
| 正则关键词 `/pattern/flags` | 近似 | 较新版本支持；旧版按普通文本 |
| 选择性逻辑 0–3 | 精确 | — |
| 常驻 / 禁用 | 精确 | — |
| 概率 | 近似 | 本地 PRNG（可设种子复现），随机源与运行时不同 |
| 包含组 / 权重 / 覆盖 | 近似 | 加权随机；group scoring 细节随版本 |
| 递归扫描 | 近似 | 轮次上限可配（默认 3） |
| token 预算 | 近似 | 粗估 token，按排序累加截断 |
| 向量化召回 | 不实现 | 需嵌入模型 |
| sticky / cooldown / delay | 不实现 | 需完整消息时序状态机 |

模拟器 UI 中每条规则都标注了「精确 / 近似 / 未实现」。

## 4. 正则

### 4.1 字段

| 字段 | 支持 | 备注 |
| --- | --- | --- |
| `id` | 读写 | 缺失时生成 UUID |
| `scriptName` | 读写 | — |
| `findRegex` | 读写 | `/pattern/flags` |
| `replaceString` | 读写 | 支持 `$1`、`$&`、`$<name>` |
| `trimStrings` | 读写 | 匹配前删除 |
| `placement` | 读写 | 见下表 |
| `disabled` | 读写 | — |
| `markdownOnly` / `promptOnly` | 读写 | 两者同开 → 校验 error（惯例：ST 视为无效配置） |
| `runOnEdit` | 读写 | — |
| `substituteRegex` | 读写 | 0 不替换 / 1 原文 / 2 转义（惯例） |
| `minDepth` / `maxDepth` | 读写 | `null` 或 `-1` 表示不限 |
| `replace_file` | 保留 | 非标准字段，存在则原样导出 |

### 4.2 placement（证据等级：惯例）

| 值 | 含义 | 证据等级 |
| --- | --- | --- |
| 1 | AI 输出（Markdown 显示） | 惯例 |
| 2 | 用户输入 | 惯例 |
| 3 | AI 输出（发送给模型） | 惯例 |
| 4 | 斜杠命令 | 惯例 |
| 5 | 世界书内容 | **待验证** |
| 6 | 推理过程 | **待验证**（较新加入） |

### 4.3 执行语义

- 同一集合内**按数组顺序**执行；`disabled` 跳过；`placement` 不匹配跳过；`minDepth/maxDepth` 按楼层深度过滤。
- 编辑器测试时对缺少 `g` 标志的表达式自动补 `g`（SillyTavern 默认全局替换），并在结果中标注。
- 替换前的 `trimStrings` 会改变索引，因此「匹配位置」按原文展示，替换按裁剪后文本执行（与 ST 语义一致的近似）。

### 4.4 安全

- 正则执行在 Worker；400ms 超时 → `terminate()` → 提示「可能灾难性回溯」。
- 静态启发式检测：嵌套量词、`(.*)*`、多个 `.*` 串联、通配符+后向断言、重叠交替。
- 导入规则不会立即执行：只有用户点击「运行测试」才进入 Worker。

## 5. 酒馆助手脚本

| 项 | 支持 | 证据等级 |
| --- | --- | --- |
| 存放于 `data.extensions.tavern_helper.scripts` | 读 / 写 | 惯例（主流卡的存放位置） |
| `data.extensions.tavern_helper_scripts` | 读 / 写 | 待验证（少数卡变体） |
| 全局设置形态 `{type:'script', value:{...}}` | 读（解包） | 惯例 |
| `id` / `name` / `content` / `info` / `enabled` | 读写 | 惯例 |
| `button.enabled` / `button.buttons[].name|visible` | 读写 | 惯例 |
| `data` / `export_with` | 原样保留 + JSON 编辑 | 待验证（含义随卡而异） |
| ES module `import` | 静态识别，不解析依赖 | — |
| 执行脚本 | **不执行** | 安全策略 |

**语法检查**：`new Function(code)` 只编译；对顶层 `await` 与 `import/export` 分别按异步/模块上下文重试，避免把「模块语法」误判为语法错误。

**依赖分析**：仅基于源码文本（import URL、importScripts、助手 API 名称、事件名、是否引用其他脚本名），属于启发式，不构成运行时依赖图。

## 6. CHARX

CHARX 是包含 `card.json` 与资源文件的 ZIP 容器。

**当前实现**：识别扩展名 → 明确提示「未内置 ZIP 解包」→ 建议解压后导入 `card.json`。不会假装成功。

原因：需要 ZIP 中央目录解析与资源落盘策略，且资源在编辑器内仅用于预览；收益低于引入解析器与安全审查的成本。

**后续可扩展点**：`core/zip.ts`（读中央目录 + `DecompressionStream('deflate-raw')`）+ assets 映射到 `CardImageInfo`。

## 7. 第三方扩展

| 来源 | 处理 |
| --- | --- |
| `data.extensions` 任意键 | 原样保留；JSON 编辑 |
| 根级未知键 | 保留在 `rootExtra`；V2/V3 导出写回 |
| `extensions.regex`（部分卡把正则放这里） | 导入时识别为「卡片内正则」；可写回 |
| `extensions.tavern_helper` | 脚本模块读取/写回 |
| 其他扩展数据（如 MVU 运行时配置） | 保留，不解释；在未知字段面板可见 |

**原则**：不认识的字段默认保留；只有用户显式删除或导出到更低版本（V1）时才会丢失，且导出前会告知。
